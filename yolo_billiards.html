项目概述
腾讯桌球游戏的台球中八自动识别系统：16 个类别（ID=球号）按"颜色 + 实色/条纹"定号体系（1-8 实色、9-15 同色条纹、0 白球），无需看清球面数字。完整走通素材采集 → 抽帧 → 去重 → 标注 → 数据集组装 → 训练 → 视频检测管线六步全流程，全部工具脚本自研。关键洞察：游戏画面与真实照片的域差距使 COCO 预训练模型零检出，而 21 张手标数据的 v0 训练即达成 0 漏检——小而准的自建数据集完胜大而泛的预训练。

素材采集策略
一局游戏 = 五种局面全覆盖
开球前/中/散开/局中/剩球少五种局面在一局 3-5 分钟录屏里天然全覆盖；换球桌皮肤采集防背景过拟合；规避微信传输（有损压缩毁画质）。素材策略先于标注——数据质量的上限在采集时就决定了。
🎞️
抽帧与去重管线
extract_frames.py + dhash_dedup.py 全自研
每秒 2 帧抽取 + 帧间差异过滤（DIFF_THR=2.0，跳过静止重复帧），零 ffmpeg 依赖（cv2 直读）；感知哈希去重相邻帧汉明距离 <6 判重复，隔离到 frames_dup（可回退不删除）——实测 252 张收敛到 86+4 张已标注回归。
✏️
labelme 圆形标注 + 格式转换
圆形工具 → YOLO txt 兼容转换
球是圆的，用 labelme 圆形工具（圆心+半径）标注比矩形框更贴合；json2yolo.py 兼容 circle 形状（圆心半径→正方形框）；认不清的球跳过不标——缺失优于错标。build_dataset.py 自动划分 train/val 并生成 16 类 data.yaml。
📐
imgsz=1280 的 8-10px 铁律
小目标检出的分辨率底线
球直径仅 35-40px（2712×1220 原图），640 输入时球剩 8-9px——恰好卡死检出下限（Level 0 零检出的根因之一）；1280 时 16-19px 进入安全区。代价是计算量 ×4——1280 是帧率杀手，所有部署平台都被它拖累。
🚀
部署帧率预估 + 优化三板斧
3050Ti 实测基准 → 边缘平台推算
本机实测 37fps（RTX 3050 Ti + CUDA）；按社区基准 × 尺寸缩放推算 Jetson Orin Nano 15-25fps（TensorRT INT8）、RK3588 11-16fps（RKNN 三核）。优化按性价比排序：① ROI 裁剪（球桌占画面 ~70%，裁掉 UI 面积 ×0.55 → 帧率 ×1.8 零精度损失）② 采集端重新构图让球更大 ③ 两段式推理（最后手段）。
识别短板（诚实标注）
  • 实色球 1-8：全部 1.00——颜色区分度高的类别先收敛
  • 白球：0.67（误判为 15/1 号）——无色球依赖形状与邻域推理
  • 条纹球 9/10/13/15：0.33-0.67——低样本类别，加数据即解决
  • 结论：短板全部指向数据分布而非模型能力——小数据集迭代路线清晰

环境与数据坑
  • PyPI 默认源 Windows torch 装出来是 CPU-only（24 个 DLL）→ CUDA 版只在官方源 --index-url cu126
  • import torch WinError 126 → VC++ 运行库 ≥14.4x 缺失
  • YOLO-World / v0 预标注 / 点选工具预填三连否决——分类准确率 <90% 时预填是负资产（错框处理成本 > 从零画框）
  • labelme 用圆形工具转 YOLO 报 0 框 → 转换脚本 dump JSON 看 shape_type 后兼容 circle
  • git-bash 裸反斜杠路径 \t \y 被转义剥除 → 一律正斜杠
  • OpenCV mp4v 输出比 H.264 大 8 倍 → imageio-ffmpeg 转码 libx264 crf26（10:1 视觉无损）
